# 语音模块追加需求：完整交付与 Windows 联调

日期：2026年10月31日。执行对象：语音模块开发负责人。适用项目：`Akira-TL/classroom-learning-support`。

## 1．本次交付要求

**必须完成真实音频的语音分离、识别、匿名说话人关联，以及处理前后音频的同时间轴交付。不能只交付算法代码、模型适配器、模拟事件或按剧本返回的转写。**

本文件是确定的追加执行要求，纠正旧交接文档中将“重叠分离、处理后音轨”写成可选或交付责任未定的内容。上述能力均为必须交付项，按本文件实施和验收。

依据原始 PRD 第3.1、6.2、6.3、10、11节及当前 MVP。原始 PRD 明确要求：至少在一组真实同步录制的两人重叠片段上展示完整处理过程，同一片段能够对照原音频与处理后音频，并输出转写和说话人标签。最新 MVP 的 M15 与语音契约 I03已承载这一要求。

当前接收的代码分支为 `codex/speech-integrated`，检查基点为 `e1dffd620239dd83e534de1917a631951676529a`。此分支是实施基础，不是完整验收已经通过的证明。

## 2．责任与最终处理链

语音侧在 `services/speech/` 维护运行环境、音频输入服务、定位与匿名说话人跟踪、去噪、重叠检测与分离、识别、音轨归档、事件输出、恢复机制及质量验证。可以使用现成模型和已有算法，但必须在交付环境实际运行。

应用侧维护教师登录和课堂权限、浏览器输入入口、结果适配、音频受控访问、教师核验、学习证据及后续教学应用。语音侧提供完整结果，应用侧完成接线；应用当前接口缺字段时必须补齐适配，不能据此取消语音交付。

完整处理链必须可执行：

**麦克风实时输入／文件按真实速度回放 → 采样与通道校验 → 语音及重叠区间检测 → 去噪／分离 → 各路真实识别 → 匿名说话人及位置线索 → 音轨与事件归档 → 教学应用时间线 → 教师对照回听和核验。**

## 3．必须实现的语音能力

| 项目 | 交付要求 |
|---|---|
| 输入 | 接受麦克风实时流和文件按真实速度回放，两条路径使用相同的处理与事件语义；不能只重播事先写好的文字 |
| 通道处理 | 保留真实通道、采样率和时钟；设备声道、声源方向、分离输出路数分别记录。单声道不能伪装为独立双通道定位输入 |
| 有效语音与重叠 | 输出实际语音区间及重叠区间；静音、噪声、缺失数据、未处理区间分别表达 |
| 去噪 | 保留原音频，输出实际去噪音轨及对应时间范围；处理导致失真时能回听原始材料 |
| 重叠分离 | 至少完成两人重叠语音的实际分离，输出可独立回听的各路音轨；只做说话人时间标注、重叠标记或复制原音轨不能代替分离 |
| 各路识别 | 对真实输入及分离后各路音轨运行实际识别模型，输出各自文字、时间范围和匿名标签；不得使用脚本台词、文件名或题目答案替代识别结果 |
| 临时、定稿与修订 | 实时输入提供临时转写和定稿；同一片段保持稳定标识，定稿后修订递增版本；撤回有明确事件，不用新片段掩盖旧结果 |
| 匿名说话人 | 标签在会话内可追踪；换座、重新聚类、分离路序改变或可靠度下降时给出重新核验信号，不能把输出第一路永久当作某位学生 |
| 位置线索 | 双通道条件满足时输出方位、单位、参考系、有效时间及可靠度；条件不满足时明确不可用，不输出伪造坐标 |
| 数学表达 | 实测“平均分”“分成四份”“四分之一”“二分之一”“一样大／不一样大”等关键表达及否定；保留原始识别结果和修订依据，题目上下文不能直接补写正确答案 |
| 失败处理 | 模型未加载、无有效识别、分离失败、仍有串音、设备丢失、显存不足、输入格式错误均有可观察状态和原因，不返回虚假成功 |

去噪、定位、分离、识别各阶段的实际实现与启用状态必须可查询。发生降级时必须披露当前运行路径，不能在能力接口中仍声称原模型已启用。

## 4．音轨与统一时间轴

每个会话必须保留原始音频。每个产生去噪或分离结果的片段必须提供对应处理音轨，满足下列条件：

1. 原始、去噪及每一路分离音频分别有稳定标识、类型、采样率、声道、样本数和时长。
2. 每路结果明确关联 `session_id`、`segment_id`、片段版本、匿名声源和会话时间范围。
3. 使用同一会话音频原点；说明音轨自身起点与会话毫秒的映射，分离裁剪不能丢失偏移。
4. 教师选择同一片段时，可在原始、去噪与各路分离音轨之间切换，比较相同时间范围。
5. 原始文件不得被处理结果覆盖；处理失败时保留原始材料及失败状态。
6. 重连缺口在时间轴上明确保留，不能把后续音频前移拼接后继续使用原时间戳。
7. 音轨读取支持按时间范围定位；正在录制和录制完成的可访问范围明确，未录制部分不假装有音频。
8. 音轨在删除课堂或会话后停止提供，文件清理失败可追踪和重试；不得借审计保留被删音频正文。

原音频及分离音轨仅供有课堂权限的教师核验。语音服务保持本机监听，应用提供授权访问入口；学生、家长和管理者不得通过音轨标识或直接地址获取其他人的录音。

## 5．事件与教学应用对接

沿用语音侧已有的 `speech.v0.1` 完整事件模型作为交付基础，包括转写、位置、音频可用、状态和结束事件。必须交付强类型模型、字段说明、正常与失败样例及验证测试。

应用当前 `app-draft-1` 是消费者早期草案，只接受部分字段。现有转换桥只能用于基础接线，**不能把丢弃完整能力所需字段后的结果当作最终交付**。以下信息必须从语音服务保留到应用适配层：

| 信息 | 必须保留的内容 |
|---|---|
| 会话与事件 | 协议版本、课堂关联、`session_id`、稳定 `event_id`、顺序号、事件类型 |
| 发言及修订 | `segment_id`、`revision`、起止时间、原始识别文字、临时／定稿／修订／撤回关系 |
| 声源 | 匿名说话人标识与会话有效范围；位置值、单位、参考系及需要重新绑定的提示 |
| 重叠 | 是否重叠、相关片段与声源，不能只留下一个无法关联音轨的布尔值 |
| 音频 | 原始、去噪、分离音轨引用和时间偏移，音轨与每路转写的对应关系 |
| 可靠性 | 可用、需核验、无法判断、失败及具体原因；数学关键表达的核验提示不得无声丢弃 |
| 缺失与结束 | 断流区间、续传位置、部分失败、最终结束与结束后的迟到结果规则 |
| 来源 | 真实实时处理、真实文件流处理、既有真实结果回放、合成测试分别标识；合成剧本不得进入真实结果入口冒充实测 |

对接要求：

- 应用课堂由授权教师创建，语音侧接受明确的课堂标识，不新增公开课堂发现接口。
- 真实事件使用私有接入令牌，不在代码、网页、日志或公开样例中保存凭证。
- 同一事件重送使用原标识和原来源；内容冲突必须报错，不能换标识绕过去重。
- 实时发送失败后保留未确认事件、原顺序和来源，恢复后可继续发送；不能用固定改标为存档回放的工具替代原实时会话恢复。
- 较旧修订不得覆盖新结果；低可靠度和失败事件必须可被应用读取，不得因文字为空直接丢掉失败事实。
- 完成最后一批结果后明确结束。结束请求、已接收事件的重复投递及结束后新事件分别处理，不能永久等待最后一块。
- 应用侧同步扩展消费模型和音轨访问；双方用同一份样例证明完整字段接收、回听与修订失效行为。服务返回200或双方类型校验通过，均不能单独代替完整联调。

## 6．原生 Windows 运行要求

部署目标是本机 Windows、RTX2060、Python3.11和uv。**不安装WSL或Ubuntu，不以Linux命令作为唯一安装和运行说明。**

必须交付：

1. `services/speech/` 独立的 `pyproject.toml`、`uv.lock` 和 `.venv`，锁定实际验证的依赖组合。
2. 支持本机GPU的PyTorch与匹配TorchAudio，记录精确版本、CUDA构建、下载来源及显卡驱动版本。
3. 实际下载并运行识别及分离模型；记录模型标识、版本、权重来源、许可和本机存放位置。
4. SeACo-Paraformer数学识别路线和实际服务所加载模型保持一致；若同时使用临时识别模型，分别记录其模型和用途。
5. 安装、自检、启动、停止、文件流测试与麦克风测试的Windows可执行入口。项目启停仍从维护的`.sh`脚本进入，可通过Git Bash调用PowerShell；不依赖`apt`、`nohup`、Linux PID或`kill`才能运行。
6. 从根目录私有`.env`读取配置；数据、模型缓存、临时音频及日志使用项目内明确路径，不写死开发者个人绝对路径。
7. 日志进入`logs/speech/`，私有音频进入`data/audio/`，模型权重进入`models/`；这些内容不进入公开Git。
8. GPU实际执行推理并报告显存与耗时。`torch.cuda.is_available()`、模型导入和健康检查只是安装检查，必须继续完成有文字和音轨输出的真实推理。
9. FFmpeg、espeak-ng、编译工具等系统依赖按实际调用声明并提供Windows安装方式，区分真实推理路径和合成评测路径；不能把合成语音工具当成真实输入的替身。
10. Windows启动脚本只处理本项目进程，不停止其他应用；首次启动不能在后台静默失败后仍提示服务可用。

本机目前已确认RTX2060，CUDA驱动初始化与设备计数成功；`nvidia-smi`管理接口曾报错。仍须以选定PyTorch构建和实际GPU推理检查完整运行能力，不能仅凭其中一项判断部署完成。

## 7．固定测试材料与质量报告

必须分别准备并标记：团队实录、独立干净录音构成的人工混合、合成语音及模拟教室。调参材料与最终评测材料分开。所有身份使用虚构标识，录音具有使用授权。

至少覆盖：单人、两人轮流、两人真实同时发言、局部和持续重叠、较轻语音、环境噪声、静音、换位、同方向不同说话人、断流重连、修订、重复、乱序、正常结束、模型失败，以及三人重叠／远场／混响压力样本。

质量报告必须包含：

- 字符错误率（Character Error Rate, CER），包含替换、删除和插入的统计口径及人工参考文字。
- 说话人日志错误率（Diarization Error Rate, DER），包含漏检、误检、归属错误及重叠区域的计分规则。
- 关键数学表达逐条的参考、识别结果与错误，包含否定和分数表达。
- 分离前后回听记录、串音和失真情况；有独立干净参考时计算适用的源分离指标，没有参考时不编造客观分数。
- 音频时长、处理耗时、首次加载耗时、峰值显存及运行版本。
- 无法可靠处理的片段、失败原因，以及需要教师修正的文字和归属数量。
- 在相同材料上比较原始音频直接转写、未修改公开方案和团队改进方案；改善、退化及无变化均须报告。

人工混合不能替代真实双人重叠录音；剧本识别不能进入真实识别质量统计；成人测试不得标成真实儿童课堂结果。

## 10．完成门槛

- [ ] 原生Windows按项目脚本可安装、自检、启动和停止，不依赖WSL。
- [ ] RTX2060上实际运行识别与分离，记录模型、依赖、驱动、耗时及显存。
- [ ] 麦克风实时流与文件真实速度回放均经过实际语音模型并进入应用课堂。
- [ ] 实时临时文字、定稿、修订及结束语义完整，重复和乱序不破坏已有结果。
- [ ] 至少一组真实同步录制的两人重叠材料完成实际分离及各路识别。
- [ ] 原音频、去噪、各路分离音轨、匿名说话人及转写可在同一时间范围核对。

- [ ] 断流、恢复、转发失败和同来源补发留有验证记录，不重复、不伪造成功。
- [ ] 教师确认与模型输出保持分离，学生身份不能由匿名声源自动决定。
- [ ] 音频权限、删除及私有资料不入Git的要求实际验证。
