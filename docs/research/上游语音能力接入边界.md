# 上游语音能力接入边界

核验日期：2026年10月30日。

语音位置识别与语音转文字由现成的上游能力提供，不属于本项目实施范围。本文记录接入时必须明确的数据含义和待确认事项；背景资料不构成模型选型决定，也不要求本项目训练、部署或优化语音模型。

## 1．本项目负责的边界

本项目接收上游发言记录、时间信息和声源线索，将其关联到课堂题目与学生，经教师核验后形成学习证据和教学支持。本项目负责适配接口、保存来源、处理修订、提供核验界面、控制发布权限和追溯教学建议的依据。

上游接口尚未确认，因此下文是供对接讨论的建议契约，不代表供应方已经支持。麦克风型号、数据传输方式和实际响应字段，应根据供应方样例收敛。音频流、转写结果流和声源位置结果可以来自不同接口，不能未经核实就假设它们天然同步。

## 2．建议向上游确认的数据契约

| 项目 | 建议要求 | 缺失时的产品处理 |
|---|---|---|
| 会话标识 | 同一堂课有稳定的会话标识；明确上游重连是否创建新会话 | 无法安全关联时暂停自动合并，由教师确认 |
| 发言标识 | 每段发言有稳定标识和修订版本，能够表示替换、拆分、合并和撤回 | 适配层需另行确定去重规则，不能只按文本是否相同判断 |
| 原始时间 | 开始、结束时间的单位、原点、时钟来源和误差范围明确 | 标记无法精确回听；不伪造词级时间戳 |
| 音频关联 | 提供可授权访问的原音频引用，或明确由谁归档音频；片段时间可映射到该音频 | 只有文字的记录明确标注“无可回听音频” |
| 结果阶段 | 区分临时转写和最终转写，并说明最终结果后是否仍会修订 | 临时结果只用于预览，不直接成为已确认学习证据 |
| 声源／位置 | 说明标签是设备通道、方位、空间坐标、匿名说话人还是供应方登记身份；包含单位和参考坐标系 | 保留原始标签与类型，显示为身份线索 |
| 重叠表达 | 说明同一时间是否允许多条发言、一个片段能否有多个候选声源、是否保留无法归属的内容 | 保留并列记录或待核验状态，不强行分配给某位学生 |
| 不可靠状态 | 区分未识别、被覆盖、上下文不足和上游处理失败；分数如有，需说明其含义 | 展示具体缺口，教师补充核验；不把不同供应方分数直接比较 |
| 事件顺序 | 有递增序号、事件标识或等价机制；明确是否乱序、重复、遗漏 | 重复不重复生成；缺口显式记录；迟到修订按版本处理 |
| 断流恢复 | 明确心跳、超时、重连续传位置、缓存时长和结束标记 | 保留已接收记录，展示缺失区间，不将断流当作学生沉默 |
| 访问权限 | 明确音频链接有效期、鉴权方式、回调校验和可删除范围 | 对学生、家长只开放已授权内容，不透传供应方凭证 |

## 3．声源、位置与真实学生身份必须分开

“来自左侧”“通道一”“说话人 A”与“学生甲”是不同含义。位置变化、设备移动或上游重新聚类，都可能改变线索与人的对应关系。本项目建议保留上游标识，另建教师确认的学生关联，不用学生姓名覆盖上游标识。

官方 FunASR 接口文档明确将声纹特征聚类得到的索引限定为录音内匿名标签；这类索引不是已登记人员身份，也不保证跨录音稳定。该资料用于说明接入时必须核实标签含义，不表示本项目采用 FunASR。[官方模型选择说明](https://github.com/modelscope/FunASR/blob/main/docs/model_selection.md)

如果供应方已提供经过登记的身份识别，应另行确认登记方式、身份更新和错误纠正契约。教师改正学生关联后，本项目将受影响学习证据和报告标记为需要重新核验，不能继续沿用旧身份的发布结果。

## 4．临时转写、上游定稿与教师确认是三个状态

建议界面分别表达：正在接收的临时文本、上游已定稿的发言、教师已核验的发言与学习证据。上游“最终结果”只表示该接口当前认可的转写结果，不能代替教师对学生归属、题目上下文和数学解释的确认。

接入层建议以发言标识和版本处理修订。教学分析记录其引用版本；上游修订或者教师纠错后，相关下游结果失效，重新核验后才能再次发布。生成过程中收到新版本时，旧任务返回的结果不能覆盖基于新版本的结果。

官方 FunASR 部署指南要求按具体协议验证采样率、分块、结束处理、重连和会话隔离，并明确不同服务协议不能互换。由此不能仅凭供应方声称“支持流式”就认定上述行为已经成立，需使用供应方实际样例验证。[官方运行时指南](https://github.com/modelscope/FunASR/blob/main/runtime/readme.md)

## 5．对接前需要供应方提供的材料

1. 实际接口文档、访问方式以及一份脱敏的完整事件样例。
2. 一份包含临时转写、定稿、修订、重叠发言和无法归属情况的样例。
3. 位置标签或匿名说话人标签的定义；其有效范围和稳定性承诺。
4. 原始音频的归档责任、回听方式，以及音频时间与结果时间的映射说明。
5. 断流、重复事件、乱序事件、重连与会话结束的约定。
6. 调用配额、费用、处理位置、数据保留与删除能力，以及演示环境是否允许使用。

这些事实未确认前，可以开发“上游结果模拟器”验证应用流程。模拟器只重放明确标注的样例事件，不展示为已接通的真实语音识别或位置识别能力。

## 6．建议的接入验收场景

| 场景 | 本项目应表现出的行为 |
|---|---|
| 正常发言从临时文本变为定稿 | 更新同一条记录，保留原始时间关联 |
| 同一事件发送两次 | 不产生两份学习证据或两次发布 |
| 定稿后上游修正一个分数 | 旧解释和建议失效，提示核验，不静默更新已发布报告 |
| 声源标签保持不变但学生换座位 | 不仅凭位置自动延续已确认身份 |
| 两个学生同时发言 | 能展示时间重叠和归属不确定性 |
| 中途断流后重连 | 已收记录保留，缺失区间可见，续传不重复 |
| 教师改归属时旧分析任务返回 | 旧结果不覆盖新版本，等待重新核验 |
| 音频链接过期或无权限 | 清楚显示不可回听；不绕过授权访问 |

## 7．已查阅但不纳入实施范围的背景资料

下列核验发生在明确“语音位置识别与转写由外部提供”之前，仅保留为解释上游能力边界的参考。

- SenseVoiceSmall 的原始论文说明其并非为流式转写设计；FunASR 的官方说明另外列出用于分块实时转写的 Paraformer-zh-streaming。工具链支持流式，不代表其中任意模型都具备原生流式能力。[SenseVoice 原始论文](https://fun-audio-llm.github.io/pdf/FunAudioLLM.pdf)、[FunASR 官方说明](https://github.com/modelscope/FunASR)
- MossFormer2_SS_16K 的官方配置为 16 kHz、两个输出说话人；官方数组示例输入为批次与时间长度两个维度，输出另有说话人维度，不能把批次维度当作双麦克风空间通道。分离结果也不直接提供学生真实身份。[官方配置](https://github.com/modelscope/ClearerVoice-Studio/blob/main/clearvoice/clearvoice/config/inference/MossFormer2_SS_16K.yaml)、[官方输入输出示例](https://github.com/modelscope/ClearerVoice-Studio/blob/main/clearvoice/demo_Numpy2Numpy.py)
- pyannote community-1 接收 16 kHz 单声道音频，多通道文件会自动平均下混；它输出说话人时间标注。模型页面声明 CC-BY-4.0，并要求用户接受访问条件、使用 Hugging Face 访问令牌。该条件仅在实际采用该模型时相关。[官方模型说明](https://huggingface.co/pyannote/speaker-diarization-community-1)

以上资料没有证明本项目已接入任何供应方，也没有证明供应方在儿童课堂中的准确性。本项目尚待确认的是实际输入接口和事件语义；具体语音模型与本地 GPU 兼容性不作为本次应用路线的前置选型结论。
