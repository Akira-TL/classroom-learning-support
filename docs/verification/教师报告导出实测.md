## 下载失败定位与真实保存

首次页面下载接口返回200，但 Chrome 下载记录显示下载错误，目标文件未生成。
重复点击真实链接可复现；直接请求8000端口也失败，排除仅由 Next.js 转发造成的解释。

最初怀疑响应的沙箱策略。已为附件补齐 `sandbox allow-downloads`，同时继续禁止脚本与外部资源，
新增响应策略回归检查先失败、修改后通过。标准规定，附件导航的目标响应沙箱标志也参与下载判断，
见 [HTML 导航与附件处理](https://html.spec.whatwg.org/multipage/browsing-the-web.html#process-a-navigate-response)。
策略修改后保存仍失败，因此不把它称为本轮下载错误已证实的唯一原因。

进一步读取专用 Chrome 自己的下载记录，确认验收配置传入正斜杠与反斜杠混合的目标路径。
仅将 `downloadPath` 改为 Windows 原生反斜杠路径，页面重新点击后下载完成：
第一份5,155字节，Chrome显示完成；第二份5,178字节，实际保存于项目忽略目录 `logs/browser-downloads/`。
文件以完整的 `</html>` 结束，包含家长反馈、版本及换行样式。归档文件与网络正文的换行编码不同，
文本内容一致，未以原始字节哈希相同作为结论。

未修改日常 Chrome 配置、安全开关或系统下载目录。
