# 浏览器文件流真实语音实测

2026年10月31日，通过项目专用 Chrome 的隔离验收页面选择 WAV，并点击文件输入。
前端、应用接口和本机 GPU 语音服务均使用实际运行实例；未注入预写转写或模拟识别响应。

## 素材与结果

素材来自本机已下载公开模型的 `example/asr_example.wav`，不是企业数据或学生录音。
输入为16000Hz、单声道、PCM16，共72363个样本，音频时长4.5226875秒。
三次实际输入分别收到19帧，最后一帧不足250毫秒；均正常结束且没有待转发数据或识别错误。
授权归档 WAV 的实际采样率和样本数与源文件一致。

实际识别正文为“嗯。 欢迎大家来到么哒社区进行体验。”。
正文保留模型原始识别用字；本次验证证明真实处理链路可用，不构成识别准确率评估。
应用保存实际语音会话、原生事件和音频引用，来源为 `upstream_live`。

第一次输入在4000个样本后实际点击暂停，等待约50秒后样本数仍为4000；
恢复后继续接收至72363个样本，没有重复或遗漏。暂停时间保留在墙钟历时中。

## 发送节奏修复

实际网络记录发现，旧实现把每次 HTTP 确认等待加入后续250毫秒发送间隔。
暂停恢复后，剩余约4.273秒音频用了约6.447秒才发出最后一帧。

修复将时序校准放在实际发送前，正常确认等待由既定采样时序吸收；
语音服务处理较慢时仍等待确认，再按采样间隔继续，避免集中补发。
新增三项确定性测试先在旧实现复现失败，再验证正常确认、慢确认及暂停恢复／停止。
这三项测试、前端类型检查和生产构建均通过。

固定构建的第三次实际页面输入记录了19次音频帧请求：

- 第一帧请求时间14917.588145秒，末帧14922.397354秒，两者间隔4.809209秒。
- 常规完整帧请求间隔约260—265毫秒，确认耗时通常约85—112毫秒，没有逐帧叠加。
- 第5帧确认耗时约466毫秒，对应下一帧请求间隔约501毫秒，实际体现处理等待。
- 最后一帧只有剩余样本，对应请求间隔约122毫秒；随后结束请求与归档正常完成。

这些时间来自 Chrome 实际网络事件的单调时钟，区别于音频时长及包含建连、推理、
结束归档等待的页面墙钟历时。浏览器调度和语音处理仍有开销，不将该结果写成严格零误差实时。

本机证据保存在 `logs/file-pacing-before.json`、`logs/file-pacing-after.json`、
`logs/browser-file-stream-sessions.json`、`logs/chrome-file-stream-paused.png` 和
`logs/chrome-file-stream-fixed-complete.png`，均不进入公开仓库。
