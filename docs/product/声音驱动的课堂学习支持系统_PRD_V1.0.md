# 声音驱动的课堂学习支持与个性化教学系统
## 产品需求文档 V1.0

**文档日期：**2026年10月30日  
**参赛方向：**思必驰「AI原生产品＋Agent」创新  
**首期场景：**小学数学课堂问答与小组讨论  
**产品形态：**双麦克风音频采集＋教师工作台＋多角色反馈界面  
**文档状态：**比赛实施版；性能指标为拟定验收目标，不代表已有实测结果。

---

## 1．产品概述

### 1.1 产品愿景

**让声音成为理解学生、支持学生的依据，让每一次表达都有机会被听见。**

课堂里，学生的回答不仅包含对错，还包含解释过程、疑问、尝试与同伴交流。多人重叠、声音较轻或表达时间较长，都可能使这些信息被遗漏。

本产品通过课堂声音采集和处理，帮助教师找到具体学习证据，形成适合不同学生的教学支持，并把课堂观察转化为下一堂课的行动。

产品不以监控学生、给学生排序或给学生贴标签为目标。

### 1.2 一句话定义

面向小学数学课堂，将多人语音转化为可核查的个人学习证据，经教师确认后，生成分层练习、提问建议与备课调整，并向学生、家长和学校管理者提供权限范围内的反馈。

### 1.3 核心价值

| 对象 | 核心价值 |
|---|---|
| 教师 | 找到容易遗漏的回答与理解问题，减少课后整理和差异化备课负担 |
| 学生 | 获得与当前学习需要匹配的练习和表达机会，并能纠正系统记录 |
| 家长 | 了解孩子已经做到什么、还需要什么支持，以及可以采取的具体行动 |
| 学校管理者 | 了解班级层面的教学支持需求和资源需求，不形成个人排名 |
| 思必驰及终端合作方 | 将语音采集与识别能力延伸到教学行动和持续使用场景 |

### 1.4 核心使用流程

**采集课堂声音 → 处理重叠语音 → 关联发言与问题 → 提取学习证据 → 教师确认 → 生成下一课支持方案 → 记录后续反馈。**

系统必须把“声音处理成功”与“教育判断成立”分开：

- 听清一句话，不代表已经准确理解学生。
- 一次错误回答，不代表学生长期能力不足。
- 未采集到回答，不代表学生没有参与。
- 低音量、停顿或语气词，不直接代表学习困难或心理问题。

## 2．问题与产品机会

### 2.1 当前问题

以下为本项目拟验证的需求假设，不能在未开展访谈前宣称已被普遍证实。

1. 多人讨论时，教师难以同时听清每位学生的解释。
2. 课后记录容易保留答案，遗漏学生如何得出答案。
3. 普通课堂摘要难以直接指导“下一堂课对谁采取什么行动”。
4. 个性化练习和提问安排需要教师额外投入时间。
5. 家长收到的反馈可能偏重结果，缺少具体支持方法。
6. 声音较轻、表达较慢的学生，其正确思路可能没有得到充分呈现。

### 2.2 产品需要回答的四个问题

- **听到了什么？** 对应哪段原始音频、哪位发言者、哪个问题。
- **证据支持什么？** 哪个知识点已表现出理解，哪里需要追问。
- **下一步做什么？** 练什么、怎么问、如何调整下一课。
- **是否需要修正？** 教师和学生如何纠正识别、归属及解释。

### 2.3 与参考截图的差异

参考截图可见的主要功能包括视频回看、课堂行为时间线、问题分类与教学反馈。

本产品的主界面和主要交付物应突出：

1. 原始混合音频与处理结果的对照。
2. 学生发言与数学知识点的证据关联。
3. 人工纠正后，分析与建议同步更新。
4. 下一堂课的具体教学调整。
5. 不同角色所需的信息与访问边界。

截图不能用于证明参考产品不具备其他能力。因此，以上属于本产品设计重点，不作“全球首创”声明。

## 3．范围与优先级

### 3.1 比赛必须完成

| 模块 | 必须交付的能力 |
|---|---|
| 课堂输入 | 上传原始音频，填写课堂主题、学生名单及教学目标 |
| 音频处理 | 展示重叠片段处理前后对照，输出转写和说话人标签 |
| 人工核验 | 修改转写、确认学生归属、标记无法判断片段 |
| 学习证据 | 将回答关联到问题和知识点，展示依据与不确定性 |
| 教学支持 | 生成分层练习、提问对象与方式建议、下一课备课调整 |
| 多角色反馈 | 教师完整工作台，学生、家长和管理者精简视图 |
| 权限控制 | 服务端按角色限制数据访问 |
| 演示证据 | 同一批录音上的原模型与改进方案对比 |
| 导出 | 可打印或下载教师确认后的教学支持报告 |

### 3.2 时间允许时完成

- 录音设备直接接入。
- 声音事件候选片段提示。
- 练习完成情况记录。
- 教师批量确认与批量驳回。
- 原课件页与备课调整建议关联。
- 处理进度、失败重试和任务恢复优化。

### 3.3 长期规划

- 40—50人真实小学课堂验证。
- 更复杂重叠、远场和混响条件下的适配。
- 教师确认身份后的多课次学习记录。
- 经验证的个体变化提示。
- 更多年级、学科和教学活动。
- 与临床合作方开展独立的声音健康研究。
- 思必驰终端的完整产品适配。

### 3.4 本次不承诺

- 稳定分离任意数量同时发言的人。
- 自动识别整班学生真实身份。
- 心理或生理疾病诊断。
- 根据声音推断智力、性格或固定学习能力。
- 学生心理健康分数、风险排名或班级排名。
- 自动替教师发布未经审核的个人评价。
- 已完成真实儿童课堂效果验证。

## 4．用户、角色与权限

### 4.1 角色定义

| 信息或操作 | 教师 | 学生 | 家长 | 学校管理者 |
|---|---|---|---|---|
| 授权班级原始音频 | 可访问 | 默认不可访问整段 | 不可访问 | 默认不可访问 |
| 本人发言与学习记录 | 可核验 | 可查看本人内容 | 查看教师确认后的摘要 | 不查看个人明细 |
| 转写与身份纠错 | 可修改、确认 | 可提交纠错申请 | 可反馈疑问 | 不可修改 |
| 个性化教学建议 | 可生成、编辑、采用 | 查看分配给本人的内容 | 查看家庭支持部分 | 查看汇总 |
| 未确认关怀线索 | 按授权访问 | 不自动展示 | 不自动推送 | 不展示 |
| 班级教学资源需求 | 可查看 | 不展示 | 不展示 | 可查看汇总 |

### 4.2 权限原则

- 家长只能访问绑定学生的信息。
- 学生不能访问同学的个人分析。
- 角色切换不能仅通过隐藏页面实现，必须在服务端限制访问。
- 家长反馈发布前必须经教师确认。
- 小样本汇总可能识别个人时，隐藏或合并展示。
- 演示账号使用成人模拟身份和虚构姓名。
- 用于演示的角色切换入口必须明确标注，不能作为正式权限实现。

## 5．教学演示场景

### 5.1 主题

**分数的初步认识：平均分与几分之一。**

具体年级和教材版本在正式部署时由教师选择；比赛样例使用自行编写的教学材料，不宣称属于某一版本的完整教学方案。

### 5.2 教学目标

学生能够：

1. 说明“平均分”的含义。
2. 判断图形是否被平均分。
3. 用分数表示平均分后的一份。
4. 解释分母与平均分份数的关系。
5. 在讨论中说明依据并回应同伴。

### 5.3 成人模拟课堂设置

四名成员分别模拟教师与三位学生。

演示包含：

- 教师提出数学问题。
- 学生轮流回答。
- 两位学生短暂同时发言。
- 一位学生解释正确但有停顿。
- 一位学生遗漏“平均分”条件。
- 一位学生回答积极，但解释依据不完整。

这些是预先设计的测试情境，必须如实标注，不作为真实学生行为样本。

### 5.4 预期教学调整

| 已确认的证据 | 支持方向 | 建议行动 |
|---|---|---|
| 把不等分图形的一份也称为四分之一 | 补充概念条件 | 安排等分与不等分图形对比 |
| 正确解释但多次停顿 | 提供表达准备 | 先独立思考，再同伴练说，最后公开表达 |
| 给出结论但缺少理由 | 加强依据表达 | 追问“哪一步说明每份一样大” |
| 重叠导致关键回答无法确认 | 补足证据 | 下一课安排一次简短解释机会 |
| 没有足够可归属的发言 | 暂不判断掌握情况 | 安排低压力的个别检查或书面练习 |

## 6．功能需求

### 6.1 创建课堂

**输入字段：**

- 课堂名称、日期、学科、年级。
- 教学主题与目标。
- 教师和学生名单。
- 活动类型：问答、小组讨论或混合。
- 可选课件与教师提供的参考答案。
- 录音来源与授权说明。
- 音频通道数量及文件对应关系。

**产品规则：**

- 未提供教学目标时，系统可生成待确认草稿。
- 分析开始前，教师需要确认教学目标。
- 音频为成人模拟、真实课堂或人工混合样本，应分别标注。
- 两路文件无法确认同步关系时，不默认执行依赖精确同步的空间处理。
- 上传失败应保留已填写的课堂信息。

**验收：** 能创建课堂并完成上传；缺失必要输入时给出明确提示。

### 6.2 音频处理与重叠片段展示

**输入：** 原始音频、通道信息和可选录音参数。

**输出：**

- 处理状态与进度。
- 原始音频时间线。
- 发言区间和重叠候选区间。
- 处理后的语音片段。
- 转写结果和匿名说话人标签。
- 无法处理或需要人工复核的片段。

**界面要求：**

- 同一片段可切换播放原始与处理后音频。
- 原始音频不可被处理结果覆盖。
- 转写可以跳转到原始录音时间。
- 处理过程不能删除原有时间对应关系。
- 分离结果可能含另一人的声音时，允许标记“仍有串音”。
- 未得到可靠输出时显示“无法可靠处理”，不补写缺失内容。

**验收：** 至少在一组真实同步录制的两人重叠片段上展示完整处理过程，并保留失败或不确定状态。

### 6.3 说话人归属与纠错

**默认流程：**

1. 系统输出匿名标签。
2. 教师结合点名、回听和座位信息绑定学生。
3. 低可靠度片段保持未确认。
4. 教师可拆分、合并或重新归属片段。
5. 涉及的学习证据与报告进入待更新状态。

**规则：**

- 分离输出的“第一路”不能永久等同于某位学生。
- 教师点名只能作为线索，不能证明随后所有声音均来自被点名者。
- 学生纠错申请保留原记录、申请原因和处理结果。
- 修改归属后，旧学生的相关分析必须移除或重新计算。

**验收：** 将一段发言从学生甲改为学生乙后，两人的报告和练习依据同步更新。

### 6.4 数学问题与回答关联

系统将教师问题、学生回答、追问和反馈组织成可回看的交流记录。

**每条记录包括：**

- 问题原文。
- 问题对应知识点。
- 学生回答原文。
- 时间范围与音频入口。
- 教师追问或解释。
- 归属确认状态。
- 是否存在重叠、识别缺失或上下文不足。

**规则：**

- “这里”“这个”“像这样”等依赖画面的表达，在没有图像或课件对应信息时不能擅自补全。
- 允许教师手动补充所指图形或题目。
- 课堂讨论中的引用、反问和自我纠正，不能机械当作学生最终答案。
- 不把发言多寡直接转换为学习成绩。

### 6.5 学习证据卡片

每张卡片回答“系统为什么提出这个建议”。

**字段：**

| 字段 | 内容 |
|---|---|
| 学生 | 教师确认后的学生身份 |
| 知识点 | 例如平均分、分母含义 |
| 证据 | 原话与音频时间 |
| 上下文 | 教师问题、后续解释 |
| 初步理解 | 系统对本次回答的解释 |
| 证据限制 | 转写不确定、回答过短、依赖图示等 |
| 建议 | 下一步检查或支持方式 |
| 确认状态 | 待核验、已确认、已修改、已驳回 |

**示例：**

> 在讨论“不等分成四块的图形”时，学生回答“有四块，所以这一块就是四分之一”。系统建议核实其是否理解平均分条件。

不能写成：

> 该学生数学能力较弱。

**验收：** 每条个人教学建议至少关联一条已确认的证据，或明确标为需要补充观察的建议。

### 6.6 表达与参与观察

支持记录：

- 可确认的发言次数与时长。
- 停顿、重复或语气词的候选位置。
- 被其他声音覆盖的片段。
- 提问后的回应情况。
- 主动解释、追问或回应同伴的内容。

**限制：**

- 这些属于课堂观察，不形成性格或疾病判断。
- 不同学生的音量不能在未控制距离、设备增益等条件时直接比较。
- 停顿可能来自思考、等待同伴、识别错误等原因。
- 音频覆盖不足时，报告必须展示信息缺口。
- 第一版不输出“注意力分数”“自信分数”等缺乏验证的综合指标。

### 6.7 个体关怀

比赛核心不依赖健康识别成功。

如接入声音事件模型，可展示：

- 疑似咳嗽等声音事件的时间位置。
- 事件是否能可靠归属到个人。
- 是否需要教师回听确认。

**产品规则：**

- 无法可靠归属时，只记录为课堂声音事件。
- 不将声音事件转换成疾病名称或患病概率。
- 不向家长自动发送健康警报。
- 不显示未经临床验证的心理状态分数。
- 教师可以形成普通关怀记录，例如“建议私下询问是否需要休息”，但应有实际情境依据。

临床合作相关内容仅进入研究规划，并单独验证适用年龄、录音条件、标签来源与模型效果。

### 6.8 分层练习生成

**输入：**

- 教学目标。
- 已确认的学习证据。
- 教师指定的题量、难度与形式。
- 可选原课件和参考题。

**输出：**

每组练习包含：

1. 对应知识点。
2. 选择理由。
3. 题目与必要图示说明。
4. 参考答案。
5. 解题解释。
6. 常见误解及教师提示。

**分层方式：**

- 概念巩固：辨别平均分。
- 解释表达：说明为什么是几分之一。
- 情境迁移：在不同图形或生活情境中应用。

练习分层针对当前任务，不将学生固定编为高、中、低能力组。

**教师操作：**

预览、修改、替换、采用或撤回。

**验收：**

- 演示题目的答案与解析经人工核对。
- 不能把数学计算或图形错误的题目发布给学生。
- 证据不足时先生成检查性练习，而非断言学生需要补差。

### 6.9 提问对象与方式建议

建议内容包括：

- 适合邀请哪位学生。
- 对应学习目标。
- 提问文本。
- 建议准备时间或表达方式。
- 选择依据。
- 备选安排。

**示例：**

> 邀请学生乙先与同伴解释“为什么必须平均分”，再选择是否向全班分享。依据是其上次解释内容正确，但表达中多次停顿。

**规则：**

- 教师决定是否采用。
- 不自动播放点名或强制学生回答。
- 不长期固定将某人作为纠错对象。
- 不按声音大小推荐“更优秀”的学生。
- 对证据较少的学生，应建议提供了解机会，而非直接评价。

### 6.10 下一课备课调整

**输出结构：**

| 部分 | 内容 |
|---|---|
| 保留内容 | 已符合教学目标、无需修改的安排 |
| 建议调整 | 需要增加、删减或改变顺序的内容 |
| 调整依据 | 对应课堂证据 |
| 建议活动 | 具体题目、讨论方式或解释任务 |
| 预计时间 | 供教师修改的建议时长 |
| 适用对象 | 全班、小组或特定学生 |
| 检查方法 | 下一课如何判断是否需要继续支持 |

**规则：**

- 不直接覆盖原备课文件。
- 教师确认后生成新版本。
- 第一版提供可编辑的备课文本；直接改写复杂课件文件不作为必需交付。
- 原课件未提供时，基于已确认教学目标生成，明确标注不是对原课件的逐页修改。

### 6.11 教师报告

按行动优先组织：

1. 本堂课哪些结论需要教师核验。
2. 哪些学生获得了充分证据，哪些仍缺信息。
3. 班级共同的知识点问题。
4. 个体学习证据与支持建议。
5. 下一课练习、提问和备课调整。
6. 采集与分析的限制。

报告中的系统草稿和教师已确认内容必须明显区分。

### 6.12 学生反馈

学生端显示：

- 本次已经做到的具体事情。
- 一项清晰的下一步练习。
- 与本人有关的记录。
- “这不是我说的”“识别错了”“我的意思不是这样”等纠错入口。

语言应适合小学生理解，不出现能力排名或医学标签。

### 6.13 家长反馈

家长端突出：

- 孩子本次具体表现出的理解。
- 教师确认的支持需要。
- 一项容易开展的家庭活动。
- 如何鼓励表达与思考。
- 向教师反馈的入口。

**示例：**

> 本次讨论中，孩子能够说出四分之一，但对“每份必须一样大”的说明还不充分。可以一起画两种分法，请孩子解释哪一种能表示四分之一。先听完理由，再一起检查。

不展示其他学生的原话、个人记录或未确认关怀线索。

### 6.14 学校管理者汇总

展示：

- 已分析课堂与教学主题。
- 音频可用情况。
- 班级层面的知识点支持需求。
- 教师采用的支持活动。
- 需要补充的教学资源。

不展示：

- 学生个人健康判断。
- 个人能力排名。
- 基于发言量的教师或学生绩效评分。
- 可直接识别某位学生的敏感小样本统计。

## 7．智能体职责与协作

这里的智能体指承担明确任务、能够调用工具并产出结构化结果的处理单元，不代表每个单元都需要独立训练一个大模型。

| 处理单元 | 输入 | 输出 | 责任边界 |
|---|---|---|---|
| 音频处理单元 | 原始音频、通道信息 | 片段、分离音频、转写、说话人标签 | 不作教育或健康判断 |
| 学习证据分析单元 | 已确认转写、题目、教学目标 | 知识点关联与待确认学习证据 | 不凭语调推断掌握程度 |
| 教学支持单元 | 已确认学习证据 | 练习、提问与备课建议 | 不自行发布给学生 |
| 关怀线索整理单元 | 可核查声音事件、教师补充 | 待人工核实提示 | 不输出疾病诊断 |
| 角色报告单元 | 授权范围内的已确认信息 | 对应角色报告 | 不扩大访问权限 |

### 7.1 协作规则

- 各单元通过明确字段传递信息，不能只传一段无法追溯的总结。
- 下游结果必须保留上游证据编号。
- 权限由程序控制，不依赖提示词。
- 课堂录音与上传文档中的内容属于分析材料，不获得系统操作权限。
- 教师修改事实后，下游相关结果标记过期并重新生成。
- 模型失败时保留已有数据，不生成虚假的成功结果。

## 8．页面与交互设计

### 8.1 页面结构

1. 课堂列表。
2. 创建课堂与上传。
3. 课堂工作台。
4. 教学支持计划。
5. 学生个人反馈。
6. 家长支持建议。
7. 学校汇总。
8. 授权、保留与删除设置。

### 8.2 教师工作台

采用三个主要区域：

- **音频与时间线：** 回听、重叠片段和处理对照。
- **证据与核验：** 发言归属、转写、数学问题和知识点。
- **下一步行动：** 分层练习、提问建议和备课调整。

默认优先展示需要处理的事项，不用大量图表掩盖实际任务。

### 8.3 关键交互

- 点击证据，定位对应音频。
- 修改转写后，提示哪些分析受到影响。
- 确认学生归属后，刷新个人证据。
- 驳回分析时，允许填写理由。
- 采用教学建议时，形成可编辑的行动记录。
- 发布家长反馈前，显示最终预览。
- 一键删除课堂时，说明将删除的音频、转写、报告和关联结果。

## 9．数据对象与状态

### 9.1 核心数据对象

| 对象 | 主要字段 |
|---|---|
| 课堂 | 主题、日期、名单、教学目标、授权说明 |
| 音频来源 | 文件、通道、采样信息、同步状态、来源类型 |
| 发言片段 | 起止时间、转写、匿名说话人、归属状态 |
| 数学交流记录 | 问题、回答、追问、知识点 |
| 学习证据 | 依据片段、解释、限制、确认状态 |
| 教学建议 | 类型、目标学生、依据、内容、采用状态 |
| 角色报告 | 接收角色、可见字段、版本、发布状态 |
| 纠错记录 | 原内容、新内容、提交者、确认者、时间 |

### 9.2 课堂处理状态

**草稿 → 已上传 → 处理中 → 待核验 → 可生成建议 → 待发布 → 已发布。**

异常状态包括：

- 输入不可用。
- 部分处理失败。
- 等待人工补充。
- 结果因纠错而过期。
- 已撤回或已删除。

### 9.3 信息变更原则

- 原始录音保留不变。
- 人工修改保留版本记录。
- 已发布报告受到实质性纠错影响时，标记旧版已失效，提供新版。
- 不静默改写家长已经看到的内容而不提示更新。
- 不把未确认结果混入已确认汇总。

## 10．技术实现候选

### 10.1 推荐处理过程

1. 读取并检查音频。
2. 确认通道和同步条件。
3. 检测有效语音与重叠区间。
4. 对需要的片段执行增强或分离。
5. 完成转写和说话人关联。
6. 由教师核对关键内容。
7. 形成学习证据。
8. 生成教学支持与角色报告。

具体模型顺序以实测决定，不要求将所有模型机械串联。

### 10.2 公开模型候选

| 组件 | 用途 | 限制 |
|---|---|---|
| ClearerVoice-Studio / MossFormer2_SS_16K | 两人混合语音分离候选 | 不等于任意人数或真实课堂已验证 |
| pyannote.audio / community-1 | 说话人时间标注与聚类 | 不等于恢复独立语音音轨 |
| SenseVoiceSmall / FunASR | 中文转写及相关语音处理 | 不作为儿童心理或疾病评估依据 |

实际选型需核对权重许可、运行条件、下载要求和真实录音效果。

### 10.3 团队拟验证的算法改进

- 双通道质量判断与选择。
- 重叠片段的针对性处理。
- 同课堂清晰片段辅助说话人归属。
- 数学词语与分数表达的识别优化。
- 对不可靠结果的识别和停止自动判断机制。

“算法创新”必须通过与未修改方案的同条件比较说明。团队履历作为执行能力介绍，不能代替技术效果证据。

### 10.4 思必驰接入

设置可替换的音频输入与识别接口。

- 使用思必驰能力时，记录具体产品、接口及承担的功能。
- 通用录音卡作为可用的采集替代。
- 演示材料清楚区分实际接入与计划接入。
- 是否满足“基于思必驰智能终端产品”的最终参赛要求，须与主办方核对；替代采集方案本身不能证明已满足该要求。

## 11．验证与验收

### 11.1 测试材料

准备三类材料，分开报告结果：

1. 团队真实同步录制的单人及两人重叠音频。
2. 使用独立干净录音构造的混合音频。
3. 额外的三人重叠、较远距离和噪声压力样本。

人工混合样本不能替代真实空间录音。成人模拟结果不能直接推广到儿童课堂。

调参样本与最终演示评测样本应分开，避免只针对已知录音优化。

### 11.2 音频验证指标

| 指标 | 目的 |
|---|---|
| 字符错误率（Character Error Rate, CER） | 比较中文转写的替换、删除和插入错误 |
| 说话人日志错误率（Diarization Error Rate, DER） | 评估漏检、误检与说话人归属错误 |
| 关键数学表达识别 | 检查“平均分”“四分之一”等是否准确 |
| 处理耗时 | 判断现场等待是否可接受 |
| 无法可靠处理片段数量 | 展示系统能力边界 |
| 人工核验工作量 | 检查系统是否真正减少整理负担 |

有独立干净参考信号时，可增加源分离指标；只有真实混合录音时，不虚构分离质量的客观数值。

### 11.3 算法改进验收

在相同测试材料上比较：

- 原始音频直接转写。
- 未修改的公开模型方案。
- 团队改进方案。

报告改善、退化及无变化的情况。若未获得改善，应如实调整技术创新表述，不挑选单个成功片段代表全部结果。

### 11.4 产品验收清单

| 编号 | 验收条件 |
|---|---|
| A01 | 上传合法音频后能进入处理流程，非法输入有明确提示 |
| A02 | 原始与处理后音频可以定位到同一片段对照 |
| A03 | 转写或身份修改后，关联分析进入更新流程 |
| A04 | 个人教学建议可追溯到证据或明确的信息缺口 |
| A05 | 所有演示练习的数学答案经人工核对 |
| A06 | 未确认个人分析不能直接发布给家长 |
| A07 | 学生和家长不能通过直接请求访问其他学生记录 |
| A08 | 系统不输出疾病诊断、心理评分或个人排名 |
| A09 | 模型失败时显示失败或待处理，不生成伪造结果 |
| A10 | 教师可修改、驳回和撤回建议 |
| A11 | 成人模拟与真实儿童课堂验证状态明确展示 |
| A12 | 删除课堂后，相关可访问音频与报告按设计清除 |

### 11.5 性能目标

比赛现场先采用录制后处理方式。

首轮实测后，记录目标设备、录音时长和实际耗时，再确定演示等待预算。未实测前不承诺固定秒数、实时处理或整节课即时报告。

可以准备预处理材料作为备用，但必须清楚说明，不能冒充现场计算结果。

## 12．数据保护与非功能需求

### 12.1 数据最小化

- 只采集完成教学任务所需的数据。
- 比赛使用团队授权录音和模拟学生资料。
- 默认不将课堂录音用于模型训练。
- 家长报告不携带其他学生内容。
- 处理日志不记录完整原始音频或无必要的敏感文本。

### 12.2 保留与删除

比赛建议默认在演示结束后删除原始测试数据；如需保留用于复现，应明确获得参与者同意并说明期限。

正式学校部署前，必须另行确认未成年人数据处理、授权、保留期限和相关责任，比赛原型不代表已经具备部署条件。

### 12.3 安全与可靠性

- 数据访问按课堂和角色隔离。
- 下载链接不得允许未授权访问。
- 上传文档和课堂发言中的指令不得触发系统权限变化。
- 外部模型服务不可用时保留任务状态。
- 重复提交不能重复发布报告。
- 教师确认、发布、纠错和删除操作可追溯。

### 12.4 可用性

- 重要状态不能仅靠颜色区分。
- 音频内容提供文字替代。
- 学生端采用简短、具体的表述。
- 对不确定结果使用“需要核对”等提示，不制造虚假的精确百分比。

## 13．比赛开发安排

正式窗口按现有赛程为41小时。以下为工作安排建议，可按现场进展调整。

| 时段 | 主要目标 |
|---|---|
| 0—4小时 | 确定演示脚本、录制测试材料、统一数据字段、验证模型能运行 |
| 4—14小时 | 音频处理与转写、归属流程；完成上传和工作台基本界面 |
| 14—24小时 | 接通学习证据、分层练习、提问与备课调整 |
| 24—32小时 | 完成人工纠错、多角色视图、权限与发布流程 |
| 32—37小时 | 处理未见样本，记录效果与失败情形，修复主要问题 |
| 37—41小时 | 演示排练、备用录屏、提交材料与运行说明 |

### 13.1 团队分工

| 成员 | 负责内容 |
|---|---|
| 项目负责人 | 产品范围、教学演示脚本、路演、PPT、材料整合 |
| 谭朗 | 应用开发、模型结果接入、权限、证据核验与报告 |
| 算法成员一 | 双通道处理、重叠分离和音频对照 |
| 算法成员二 | 转写、说话人归属、测试标注和效果评估 |

### 13.2 范围缩减顺序

时间不足时依次缩减：

1. 复杂视觉装饰。
2. 学校管理者图表。
3. 自动课件文件改写。
4. 声音事件与关怀提示。
5. 实时录音接入，保留文件上传。

必须保留：

**音频对照、证据核验、教学调整、角色隔离和真实演示说明。**

## 14．三分钟演示设计

| 时间 | 内容 |
|---|---|
| 0:00—0:20 | 说明课堂问题：学生的解释可能被重叠声音掩盖，普通摘要无法直接支持下一课 |
| 0:20—0:55 | 播放同一段原始混合录音与处理结果 |
| 0:55—1:25 | 展示关键数学回答、说话人归属及可回听证据 |
| 1:25—1:55 | 教师纠正一处归属或解释，相关分析同步更新 |
| 1:55—2:30 | 展示分层练习、提问方式和备课调整 |
| 2:30—2:50 | 对比教师与家长所见内容 |
| 2:50—3:00 | 说明成人模拟验证范围、实际改进及下一步真实课堂验证计划 |

### 路演必须讲清

- 哪些能力来自公开模型。
- 团队修改了什么。
- 在什么条件下进行了比较。
- 有哪些失败或不确定情况。
- 本次实际使用了哪些思必驰能力。
- 没有开展疾病诊断，也没有完成真实儿童课堂验证。

## 15．评分维度对应

| 评分项 | 权重 | 本项目应提供的证据 |
|---|---:|---|
| 技术完成度 | 30% | 从录音到教学建议的完整流程；纠错和失败处理可运行 |
| 创新性 | 25% | 团队算法修改的比较结果，以及声音证据驱动教学调整的具体机制 |
| 场景与应用价值 | 25% | 一个数学主题中的具体学习需要、教师可采取的行动与可核查依据 |

## 16．主要风险与处理

| 风险 | 产品处理 |
|---|---|
| 两麦远场录音质量不足 | 实测摆位；保留原音频；明确可用范围 |
| 重叠人数超过模型能力 | 标记无法可靠处理，安排补充观察 |
| 声音被分离失真 | 回听原音频，不仅凭处理后结果判断 |
| 说话人归属错误 | 教师确认与学生纠错；下游结果同步更新 |
| 数学表达识别错误 | 优先核验关键词、分数和推理条件 |
| 低音量被解释为学习困难 | 仅描述可观察表现，结合内容与情境 |
| 缺少发言被解释为没学会 | 显示证据不足，建议补充检查 |
| 生成练习数学错误 | 人工检查后发布 |
| 家长反馈引发标签化 | 聚焦具体表现与支持行动，不给固定等级 |
| 实际未接入思必驰产品 | 明确状态，核对赛题要求，不夸大适配完成度 |
| 模型运行慢或失败 | 录制后处理、进度显示、备用材料明确标注 |

## 17．后续验证计划

### 第一阶段：成人模拟

验证声音处理、归属纠错、证据追溯和教学建议流程能否运行。

### 第二阶段：教师试用

请小学数学教师评价：

- 证据解释是否合理。
- 建议是否可用于下一堂课。
- 核验成本是否可接受。
- 哪些内容应由教师决定。

### 第三阶段：真实课堂小规模研究

在具备适当授权与实施条件后，验证儿童语音、距离、混响与小组讨论中的实际表现。

不直接以成人测试指标替代儿童测试结果。

### 第四阶段：持续教学支持

教师逐课确认身份，将学习记录与后续练习表现关联，研究教学建议是否真正帮助教师和学生。

### 第五阶段：独立健康研究

结合现有临床合作资源，单独开展声音健康相关研究。未取得适用于目标年龄与课堂条件的证据前，不将其作为疾病评估产品功能。
