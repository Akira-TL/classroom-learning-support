# 声音驱动课堂学习支持系统：MVP 产品需求

日期：2026年10月30日。状态：产品范围与 DeepSeek 云端模型已确认，语音接口待真实联调验证。

## 1．产品目标与依据

让教师从课堂发言中找到可核查的学习证据，纠正识别或理解偏差，再生成练习、提问安排和下一课教学调整。

2026年10月31日补充：同时关注学生本人的课堂体验与关怀。保留嘈杂原声，
展示分离后的人声及环境声音线索；将同一学生不同时期的可核查记录进行比较，
支持教师了解情况、记录跟进，并分别向学生和绑定家长发布经确认的反馈。
声音处理不以消除环境声为唯一目的，原声和处理音轨并存。

新增“学生关怀”页面：左侧选择学生，右侧展示上周与本周的观察、对应来源、
采集条件和教师跟进记录。声音的音高、音量等只在有实际测量值和单位时展示；
缺失、录制条件变化及样本不足均须可见。不从声音直接判定性格、疾病或抑郁症，
不将变化提示作为诊断或自动向家长报备。教师先核实情况再决定发布内容。

演示支持明确标注的成人模拟资料，展示嘈杂原声、分离音轨、个人前后比较和不同角色报告。
“全部声音事件已识别”“已训练并跑通10人”“自研算法优于其他设备”等成果表述，
必须有对应实现与实测记录；当前新增愿景不能代替完成证据。咳嗽、掉笔等声音事件
仅在实际检测和人工核实后展示，尚未识别时不能补造标签或解释为健康与行为结论。

同日进一步确认演示分工：用户后续提供音频、语音识别文本、时间戳及声音特征标签值。
应用负责导入、定位回听、同一学生的上周与本周标签次数及时间分布对比，
并调用 DeepSeek 形成待教师核验的变化解释、跟进问题及分角色反馈草稿。
不以本轮训练声音事件检测模型作为演示前提。标签保留原始名称、来源、时段与版本；
外部提供的“走神”“睡觉”等状态标签不能自动当作已核实行为。
没有采集记录的时段显示缺失；只有具备实际采集时长时才计算出现频率。
“咳嗽增多，建议了解是否身体不适”“新增鼾声记录，建议了解睡眠情况”属于待核实提示，
不得直接改写成已感冒、睡眠不足或疾病判断。用户数据到位前，页面提供明确的导入空状态，
任何可选演示样例都须与实际导入数据分开并标明来源。

原始需求见 [PRD V1.0](声音驱动的课堂学习支持系统_PRD_V1.0.md)。原稿作为完整历史快照保留；本文件记录本次讨论确认的 MVP，冲突处以本文件列出的最新分工为准。

已确认的变化：

- 保留教师、学生、家长、管理者的完整教学反馈闭环，不按比赛时长裁剪。
- 不绑定麦克风品牌或型号；同时支持文件按真实速度回放为音频流，以及麦克风实时输入。
- 语音位置识别和语音转文字由独立语音模块提供，本项目负责接入和教学应用。
- 实时展示上游转写，按片段更新待核验内容；教学建议在教师核验后生成。
- 语音模块的具体能力、接口和联调责任通过独立交接文档对齐。
- 教师端证据解释、练习与教学建议直接使用 DeepSeek 云端模型，不开发多供应商兼容层；调用只发送必要的匿名模拟教学内容。

重叠语音分离、转写及处理前后音频对照是比赛必须交付的能力，由语音模块负责实现、运行和质量验证，教学应用负责接入、受控回听和教师核验。原始PRD第6.2节要求至少在一组真实同步录制的两人重叠片段上展示完整处理过程；纯事件回放或按剧本返回文字不能满足此项。GPU资源用于运行语音模块，不作为教学应用服务自身的前提。

## 2．产品形态与首个场景

产品形态为教师主导的网页工作台，配套学生、家长和管理者反馈页面。音频输入和语音结果通过适配层接入，不直接依赖某个硬件产品。

首个完整场景为“分数的初步认识：平均分与四分之一”。使用成人模拟的教师与三位学生、人工核对过的题干及图形。验证范围是教学工作流与接入行为，不将成人模拟结果当作儿童课堂效果。

该场景的人工判定依据见[演示数学参考](演示数学参考.md)，尤其区分“每块都是四分之一”与“其中一块恰好为四分之一”。

## 3．模块责任

| 模块 | 本项目承担 | 上游或协作方承担 |
|---|---|---|
| 输入入口 | 文件回放、麦克风入口、会话状态、归档对接 | 硬件驱动、设备特有采集能力 |
| 语音结果 | 接收、展示、保存修订、关联回听 | 位置识别、转写及其模型部署与质量验证 |
| 重叠声音 | 展示原始与分离后音频、对应转写及匿名标签，支持同时间范围对照回听 | 实际分离、各路识别、时间对齐与质量验证 |
| 身份核验 | 将声源线索与学生名单分别保存，由教师确认关联 | 提供声源标签定义及有效范围 |
| 教学应用 | 题目关联、学习证据、教学建议、发布与纠错 | 教师提供或确认教学目标、题目与解释 |

语音识别最终结果不等于教师确认结果；声源位置、匿名说话人和学生身份必须分别表达。

## 4．核心使用流程

1. 教师创建课堂，确认主题、目标、题目图形与名单。
2. 选择实时输入或回放；界面持续显示接收状态、临时转写与上游定稿。
3. 教师将发言关联到题目和学生，回听并修正文字或身份。
4. 系统基于已核验发言与题目上下文生成待核验学习证据。
5. 教师确认或驳回证据，再生成练习、提问建议和下一课调整。
6. 教师检查题目答案、编辑内容，预览并按角色发布。
7. 学生与家长可反馈记录问题；教师处理后，受影响内容失效并重新核验。
8. 记录建议是否采用及后续检查结果，形成下一堂课可以接续的记录。

## 5．功能要求

### 课堂和题目

课堂包含名称、日期、名单、教学目标、数据来源和授权说明。首个场景采用固定题目编号及已核验图形，避免“这里”“这一块”缺少上下文。

未确认目标或题目上下文不足时，可以保留发言并提示补充，不输出确定的知识掌握判断。

### 音频与结果流

实时输入和文件回放使用相同会话及事件契约。文件回放可暂停与继续；界面显示真实来源。只有回放音频并重新调用真实上游处理，才能标注为现场处理。

已记录结果回放或模拟事件必须单独标识；没有上游时，麦克风输入不能伪装为已接通识别服务。

临时文本可持续更新；上游定稿保留稳定片段标识和版本。重复事件不新增记录，乱序修订不得覆盖更高版本。断流记录缺失区间，不被解释为学生沉默。

### 教师核验工作台

同屏展示题目与图形、发言时间线、声源线索、学生归属和学习证据。支持定位原音频、修改转写、确认身份、标记无法判断、驳回证据。

教师核验文字、身份和教育解释是不同操作，应分别记录结果。系统不能因上游标记为最终转写就自动确认学习证据。

### 学习证据

证据必须指向具体题目、发言及版本，展示原话、解释、限制和教师确认状态。只有本次回答能支持的结论才能写入；发言次数、停顿、声音位置本身不证明掌握程度。

例：学生把不等分图形的一块称为四分之一，形成“需要核实平均分条件”的待确认记录。若图形未提供，应先补充上下文。

### 教学支持

输出概念巩固、解释表达和情境迁移练习，附题目、图示、答案、解释及证据来源。首个版本优先使用人工核对的图形与题目模板，生成内容须再次核验。

同时提供提问对象与文本、准备方式和备选安排，以及下一课保留内容、调整活动、对应依据和检查方法。教师可以编辑、采用、撤回；不覆盖原备课文件。

### 四类角色

| 角色 | 可见内容 | 关键操作 |
|---|---|---|
| 教师 | 授权课堂的原音频、转写、证据和建议 | 核验、编辑、发布、撤回、处理纠错 |
| 学生 | 本人已发布反馈及练习 | 查看、提交纠错、记录练习反馈 |
| 家长 | 绑定学生的已发布摘要和家庭活动 | 查看、提交疑问 |
| 管理者 | 授权范围内课堂与资源需求汇总 | 查看汇总，不读取个人明细 |

演示使用固定虚构账号与绑定关系。角色切换入口清楚标注为演示入口，服务端仍须按登录主体限制对象访问。

学生和家长默认仅接收经过筛选的文字及题目，不直接开放包含他人声音的重叠音频。管理者少于 5 名不同学生的个人表现相关汇总隐藏；筛选后的分组同样检查。此为已确认的演示产品规则，详见[授权决定](../../.scratch/mvp/issues/05-access.md)。

## 6．修订、失效与发布

以下为拟实施的行为契约，需作为联调和产品验收的重点：

- 发言、身份关联、题目、证据、建议和报告分别保存版本，不使用一个课堂状态替代全部对象状态。
- 教师修改事实或上游提交新版本后，受影响证据和建议立即标为待重新核验。
- 人工编辑内容保留为草稿并标明依据变化，不静默覆盖，也不自动沿用确认状态。
- 分析任务绑定输入版本；过期任务的返回值仅保留审计信息，不覆盖当前结果。
- 发布按接收对象生成明确版本；重复请求不产生重复发布。
- 已发布内容失效或撤回后，站内页面和受控下载入口停止提供旧内容，并提示等待新版。
- 已经下载到用户设备的文件无法远程收回；文件应带版本、时间和状态查询入口。
- 课堂列表可以显示进度摘要，但真实状态由接收任务、核验记录与发布版本共同决定。

## 7．最小可靠性要求

接口或模型失败时保留已收数据和人工修改，允许从失败步骤重试。区分处理中、部分完成、失败、等待补充和结果过期。

发布前服务端检查角色权限、输入版本、教师确认和接收对象。上传材料中的命令仅作为分析文本。原始录音、凭证和真实学生资料不进入公开仓库。

删除覆盖课堂音频、衍生片段、分析和受控报告入口；审计中仅保留必要的操作事实。对外部语音服务的数据删除责任另行确认，不宣称本地删除等于供应方删除。

## 8．验收场景

| 编号 | 可观察的通过条件 |
|---|---|
| M01 | 同一测试音频经文件回放与真实输入两种入口进入统一课堂会话，来源标识准确 |
| M02 | 临时文本变为定稿时更新同一发言，不产生重复证据 |
| M03 | 重复事件、乱序版本与断流恢复不造成覆盖新结果或重复发布 |
| M04 | 上游位置标签不被自动当作真实学生身份 |
| M05 | 修改学生甲的发言归属为乙后，双方关联证据和建议进入正确的失效与重核流程 |
| M06 | 缺少题目图形时不生成确定的概念错误结论 |
| M07 | 每条个人建议关联已确认依据；信息不足的建议明确用于补充检查 |
| M08 | 演示练习的题干、图形、答案和解释经人工逐题核对 |
| M09 | 未确认或过期内容无法发布，旧任务不能覆盖新版本 |
| M10 | 学生和家长直接请求其他人的资源时被服务端拒绝 |
| M11 | 真实服务失败与模拟回放均如实展示状态 |
| M12 | 撤回后站内旧报告不可继续读取，已下载副本的限制明确说明 |

## 9．效果验证

分别评价上游能力与本项目价值。语音准确性由语音模块提供评测证据；本项目验证事件接入正确性、教师核验耗时、所需修正次数、建议可追溯率、数学题正确性与教师采用反馈。

先固定未用于调试的测试材料及人工参考，再对比“人工查看转写整理建议”和“使用本系统核验生成建议”的任务过程。样本量、延迟预算和可接受核验成本由首轮真实测量后确定，不把拟定目标写成实测结果。
