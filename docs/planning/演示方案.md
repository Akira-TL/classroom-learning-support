# MVP 演示方案

2026年10月31日赛事补充：按[赛事约束与规格调整](赛事约束与规格调整.md)记录企业资源与开发来源。当前没有企业设备、账号与数据，合成流程不作为企业真实联调证据；额外准备核验、纠错、失效和重新确认的快速演示，并能复位。真实失败与预先生成材料均如实标记。

日期：2026年10月30日。状态：已确认两种流输入，演示内容按完整教学闭环组织。

## 1．演示故事

在“平均分与四分之一”的课堂中，一句容易被遗漏的回答被记录下来，教师核实其含义，系统形成有依据的教学安排，并向学生和家长发布适合他们的反馈。

使用成人模拟教师与三位学生，姓名虚构。准备等分和不等分图形、教师问题、参考解释及一段重叠发言。教师与语音模块的作用分别说明。

## 2．两种输入方式

- 文件回放：按真实时间推进，可暂停继续。分清“回放音频经真实接口处理”和“回放已记录的接口结果”。
- 实时麦克风：现场表达，展示上游实时返回的内容。接口未连接时如实显示不可用，不用预制答案代替。

所有页面显示当前来源。上游未就绪时，可展示标为模拟的事件回放，以验证教学应用交互；不据此声明语音能力已经集成。

## 3．演示步骤

| 步骤 | 屏幕内容 | 必须让观众看到的变化 |
|---|---|---|
| 创建课堂 | 目标、名单、题目与图形、输入选择 | 本次分析具有具体教学背景 |
| 接收课堂表达 | 时间线、临时转写、上游定稿与声源线索 | 同一条发言逐步完善，位置没有被当作身份 |
| 回听核验 | 点击原话定位音频、确认学生与题目 | 每个判断能追溯到素材 |
| 查看证据 | “有四块就是四分之一”与不等分图形 | 系统提出待核实的平均分条件问题 |
| 纠正归属 | 教师把一段发言从甲改为乙 | 甲的旧依据失效，乙的证据等待重核 |
| 形成建议 | 对比练习、追问文本、下一课活动 | 建议具体对应已确认的证据 |
| 发布反馈 | 教师预览、学生练习、家长家庭活动 | 各角色接收不同内容且有服务端访问限制 |
| 汇总与反馈 | 管理者基础汇总、采用情况与纠错入口 | 教学支持可以接续到下一堂课 |

处理前后音频对照是上游能力展示：只有上游实际提供同片段处理结果时展示，并注明处理来源；缺少时展示原音频和不确定状态。

## 4．需要准备的材料

人工核对的题目与图形、授权模拟音频、上游结果样例、预置角色账号、参考转写、证据与建议的验收预期、失败及修订场景。

现场演示一次正常流程及一次纠错。测试还应覆盖重复事件、断流、旧任务迟到、数学上下文缺失与越权请求。备用录屏标明录制时间和数据来源。

## 5．展示布局建议

教师端采用题目背景、课堂时间线、证据核验三部分相互定位；教学建议在证据确认后出现。反馈端适合窄屏阅读，优先呈现一个具体进步与下一步行动。

不在学生和家长页面暴露事件序号、模型提示词或任务队列等实现细节。需要让使用者作决定的状态，如“等待教师核验”“内容已撤回”，应明确可见。
