# 教学应用技术路线

日期：2026年10月30日。状态：建议路线，待本地 Markdown 决策议题收敛。

## 1．已确认的责任边界

本项目开发教学应用与语音结果适配层。定位和转写由独立语音模块提供；重叠分离与音轨输出纳入交接讨论。具体麦克风型号不固定。

应用支持文件回放音频流和麦克风实时输入。持续接收不意味着每一步分析实时完成：临时转写即时展示，发言定稿和教师核验后再形成证据及建议。

## 2．建议架构

```mermaid
flowchart LR
    A[麦克风或文件回放] --> B[语音模块：协作方]
    B --> C[接入适配与事件保存]
    C --> D[课堂时间线与教师核验]
    D --> E[学习证据分析]
    E --> F[教师确认]
    F --> G[练习、提问与下一课建议]
    G --> H[角色发布与反馈]
    H --> D
```

浏览器直接采集或协作方直接推流都可通过适配层接入；不得假设两个结果服务的时钟天然同步。应用模型调用只接收业务层按权限筛选的上下文。

## 3．技术建议与决策状态

| 部分 | 建议 | 理由与待验证点 |
|---|---|---|
| 网页 | Next.js、React、TypeScript、Tailwind CSS | 遵循项目既有默认版本线；正式安装前验证兼容版本并锁定依赖 |
| 应用接口 | Python、FastAPI、Pydantic，使用 uv 与 .venv | 强类型事件校验、独立接入接口与模型调用；最终是否需要独立服务待接口复杂度确认 |
| 双向会话 | WebSocket | 支持控制、数据事件与确认；实际传输必须适配供应方协议 |
| 业务存储 | PostgreSQL | 保存对象版本、任务、角色与发布事务；部署位置待确定 |
| 音频存储 | 本地受控目录起步，通过存储接口访问 | 不暴露裸目录；迁移对象存储时保留访问权限与生命周期约束 |
| 后台任务 | 独立任务执行器与持久任务表 | 支持重试、幂等和版本检查；先不引入与业务无关的分布式组件 |
| 教学生成 | 服务端直接调用 DeepSeek 云端接口 | 用户已确认，不建设多供应商兼容层；强类型校验、教师确认与失败处理保留 |
| 图形题 | 人工核验模板与确定性图形 | 优先控制数学正确性，生成内容仍需教师确认 |

这些是供评审的建议，不代表组件已经安装、功能已经实现或用户已经确认全部选型。语音模块自行决定其模型与运行环境。

## 4．事件与版本处理

建议接入层将供应方格式规范化为带有会话、事件标识、序号、发言标识、修订号、时间范围与来源类型的明确事件。

临时转写、定稿、修订、声源变化、重叠提示、音频可用、断流与结束分别表达。字段草案见 [语音模块对接契约](../integration/语音模块对接契约.md)，待双方确认后才冻结。

保存上游原始事件与应用归一化结果的关联；人工修正独立保存，不回写供应方原始输出。所有下游任务绑定输入版本，发布前再次校验。

## 5．阶段路线与完成条件

| 阶段 | 要解决的问题 | 可进入下一阶段的证据 |
|---|---|---|
| 接口对齐 | 上游提供什么，如何对齐音频与结果 | 一份双方确认的契约及脱敏事件样例 |
| 应用贯通 | 不依赖实时服务时，教学闭环是否成立 | 明确标注的回放数据完成核验、证据、建议、发布与纠错 |
| 真实联调 | 实时输入能否得到相同语义的事件 | 正常、重叠、修订、断流四类实际接口记录 |
| 教学质量 | 数学解释与建议能否使用 | 教师对题目、证据和练习的逐项审核记录 |
| 发布验证 | 多角色访问、版本与撤回是否正确 | MVP 验收场景通过，真实失败不伪装为成功 |

阶段依据依赖关系排列，不设比赛倒计时。

## 6．运行与发布

运行和停止脚本统一保存在 `scripts/`，日志写入 `logs/`；前端和接口使用独立进程，凭证保存在本机环境配置中。当前阶段只规划，不创建服务或修改系统驱动。

本机能识别 RTX 2060，但显存和计算可用性未验证。定位与转写既然由上游负责，GPU 检查不阻塞教学应用方案；若上游使用此电脑，应在交接中另行验证。

公开仓库保存代码、规格、合成样例与协议；原始录音、真实学生资料、模型权重与访问密钥不上传。

## 7．资料依据

- FastAPI 官方提供 WebSocket 接收、发送与断连处理示例；这支持其作为接入层候选，不能替代持久重连和业务幂等设计。[FastAPI WebSockets](https://fastapi.tiangolo.com/advanced/websockets/)
- 浏览器 `getUserMedia` 需要用户授权和安全上下文，实时麦克风演示应在实际浏览器与访问地址上检查。[MDN getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)
- `MediaRecorder` 分块回调时间并不保证精确等于请求间隔，不能仅靠块序号计算音频时间。[MDN dataavailable](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/dataavailable_event)
- 上游输出的标签、修订与时间基准问题见 [接入边界研究](../research/上游语音能力接入边界.md)。
