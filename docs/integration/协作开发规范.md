# 教学应用与语音模块协作开发规范

日期：2026年10月30日。适用双方：教学应用负责人、语音模块负责人及其开发 Agent。

## 1．开发位置与职责

公开仓库为 `Akira-TL/classroom-learning-support`。语音侧在仓库的 `services/speech/` 内开发；教学应用侧维护课堂、教师核验、学习证据、教学建议和角色反馈。

| 范围 | 主要负责方 | 协作要求 |
|---|---|---|
| `services/speech/` | 语音侧 | 维护本模块代码、依赖、测试、运行说明与适配器 |
| `docs/integration/语音模块对接契约.md` | 双方共同 | 语音侧核实实际能力，应用侧核实消费行为；变更同时说明影响 |
| `contracts/speech/` | 双方共同，按需建立 | 存放确认后的协议定义和合成事件样例，不复制两份相互漂移的契约 |
| 产品文档与教学应用代码 | 应用侧 | 按 MVP 和已确认决策开发，不把语音算法任务转移给应用侧 |
| 根配置、公共脚本、议题与共享依赖 | 修改发起方协调双方 | 在变更说明中列出使用方和迁移影响，避免无意覆盖 |

语音侧负责定位与转写的现成能力接入和运行；重叠分离、处理后音轨仍是待确认交付项。应用侧负责接收结果、回听入口、学生身份核验及下游版本失效。

开发目录已经建立，但当前没有可运行服务。最终协议未冻结，不得把目录初始化理解为已经完成语音接入。

## 2．语音模块内部组织

语音侧可在 `services/speech/` 下建立 `src/`、`tests/`、`scripts/` 和模块依赖声明。Python 使用 uv 与模块自己的 `.venv`；具体技术栈由现成能力确定，不要求重新实现已有算法。

模块启停通过本模块 `scripts/` 中的 `.sh` 脚本；首次实现时补齐启动、停止、健康检查及 Windows 所需工具说明。运行日志放根目录 `logs/speech/`，实际音频放根目录 `data/audio/` 或另行授权的位置，均不提交。

设备参数、服务地址和凭证通过配置传入。可提交没有真实密钥的配置示例；不将本机绝对路径或设备型号写死在共享协议中。

## 3．分支与文件归属

- 双方使用各自克隆或已授权的独立工作区，避免两个 Agent 同时修改同一检出目录。
- 分支使用 `codex/speech-主题` 或 `codex/app-主题`；按单一修改目的形成提交。
- 修改共享契约前记录本地议题，列明字段、语义、使用方及兼容性影响。
- 只暂存本方修改；不重置、清理或顺带提交他人文件，不强制推送覆盖历史。
- 正式提交使用 Guard；普通 push 不触发云端 CI。
- 合入前提交变更说明、相关本地测试结果和剩余限制。跨模块行为变化需双方核对同一份样例。

## 4．接口变更

当前对接契约是应用方提案。语音侧先提供真实脱敏响应，再共同确认字段含义、时间基准、匿名声源范围、修订、重复、乱序、断流与结束行为。

冻结时记录协议版本与双方确认依据。增加可选字段不得改变已有字段含义；删除、重命名或改变时间与修订语义，必须形成明确的版本迁移方案。未识别版本应返回可诊断错误，不静默按旧协议处理。

双方共用 `contracts/speech/` 中按需建立的合成样例。生产者应证明输出符合契约，消费者应证明相同样例产生预期状态；不能仅靠两边都能启动判定联调成功。

## 5．任务与依赖

议题以 `.scratch/` 内 Markdown 为唯一权威。当前决策规划在 `.scratch/mvp/`；应用实现任务审批后放 `.scratch/application/`。语音侧可按相同规则建立 `.scratch/speech/`。

跨工作目录的依赖必须使用明确文件链接，并在任务前置条件中说明；单个目录内 `Blocked by` 继续使用编号。任何未解决的外部依赖都阻止对应任务进入执行，不能只检查本目录编号。

开始前按项目规则领取，完成后记录验收证据和提交。目录归属不是并发互斥；共享身份和共享目录下默认串行操作。

## 6．联调顺序与交付清单

1. 语音侧确认实际服务与责任，提供样例及启动说明。
2. 双方确定协议版本，验证正常发言与原音频定位。
3. 验证修订、重复、乱序、重叠、断流、恢复与结束。
4. 验证应用将转写定稿、学生归属和教师确认分别保存。
5. 验证纠错使旧证据与建议失效，旧分析任务不能覆盖新版本。
6. 以麦克风实时输入和文件回放两条路径各完成一次教学流程。

交付应附服务启动停止方法、配置说明、协议版本、合成样例、验收记录和已知失败条件。验收采用对接契约 I01—I09；没有提供的能力明确标注，不用模拟结果替代真实联调结论。

## 7．素材与公开边界

公开仓库只保存代码、规范、合成样例和获得明确授权的材料。凭证、模型权重、真实学生资料及课堂原音频不上传。带多人声音的音轨不能直接作为学生或家长可访问资源。

语音模块的运行结果只作为分析材料，不能携带能改变应用权限的指令。服务器校验鉴权、会话归属和输入格式；不能只依赖模型提示词。
