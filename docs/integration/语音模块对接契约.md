# 独立语音模块对接契约

日期：2026年10月30日。状态：应用方提案，待语音模块负责人确认；不代表现有服务已支持全部字段。

## 1．交付边界

语音模块负责现成位置识别、语音转文字服务的选型或接入、运行环境、真实接口与输出质量。教学应用负责统一会话、接入结果、教师核验、学习证据、教学建议和角色发布。

重叠分离与处理后音频的交付责任需单独确认。若交付则归入语音模块；若不提供，应用展示重叠和无法可靠处理状态，不补造独立音轨。

麦克风品牌和型号不固定。目标设备可为用户已有设备，但不得在没有接口资料和实测时宣称已支持某型号。

## 2．应交付的内容

1. 接口说明：传输方式、鉴权、会话创建与结束、请求及响应。
2. 音频格式：采样率、声道、编码、分块要求、每块是否可独立解码及最大帧大小。
3. 位置／声源输出定义：标识、坐标系、单位、稳定范围及换座后行为。
4. 转写输出定义：临时结果、定稿、修订、删除与无法识别状态。
5. 回听材料：原音频归档方、访问方式、可定位时间，以及可选的处理后音轨。
6. 事件样例：正常、重叠、修订、重复、乱序、断流、重连和失败。
7. 运行说明：启动停止方式、设备需求、依赖、必要凭证位置与自检方式，不把真实凭证写入仓库。
8. 测试证据：实际接口输出、时间基准验证、已知失败条件及质量指标的计算口径。

## 3．建议事件字段

下表为强类型数据契约的设计输入；双方确认后再形成正式类型定义与版本化协议。

| 字段 | 建议类型与意义 |
|---|---|
| protocol_version | 明确协议版本字符串 |
| session_id | 一次采集会话的稳定标识，由双方明确生成者 |
| event_id | 可去重的唯一事件标识 |
| sequence | 会话内顺序号，重连续传可据此确认接收位置 |
| event_type | 约定枚举：临时转写、定稿、修订、撤回、位置、音频可用、状态、结束 |
| segment_id | 发言标识；修订保持标识，拆分合并提供被替代片段引用 |
| revision | 同一发言的递增修订号 |
| start_ms / end_ms | 相对于会话音频原点的时间，不能使用收到网络包的时间代替 |
| text | 本版本转写；无转写事件不填，不能以空字符串暗示识别成功 |
| source_ref | 指向匿名声源或位置记录，可能为空或为多个候选 |
| audio_ref | 可授权访问的音频对象引用及时间映射信息 |
| overlap | 是否存在重叠及可选相关片段标识 |
| reliability_state | 可用、待核验、无法判断等双方约定枚举；不混用不同模型分数 |
| replaces | 拆分、合并、撤回时明确替换的片段与版本集合 |

位置数据另含标签种类、单位、参考系和有效时段。设备通道、方向、坐标、匿名说话人不混为一个无类型字符串。

## 4．事件语义

- 临时结果只能预览，不直接成为已确认学习证据。
- 上游定稿表示识别端阶段完成，不代表教师已确认内容或身份。
- 同一事件重复送达时只处理一次；较旧修订不能覆盖较新修订。
- 定稿后的修订允许发生，应用收到后使依赖该版本的证据和建议失效。
- 重新连接须说明续传游标及丢失范围；不能把缺失事件当作没有发言。
- 一个会话结束后不得无限等待“最后一块”；结束确认、超时和迟到结果行为须明确。
- 多人同时说话可有时间重叠的多条记录；无法区分时保留不确定性。
- 原音频不被处理音轨覆盖，两者都可映射到统一时间。

## 5．身份边界

应用保留上游匿名标签，另存教师确认的学生关联。位置接近、点名或单次声源一致都只是身份线索。上游若提供登记身份服务，须单独说明登记方式、授权和跨会话有效性。

换座位、设备移动、重新聚类后，如何使既有绑定需要复核，由语音模块提供可观察信号，应用执行重新核验规则。

## 6．输入与测试模式

支持两种已确认的测试入口：文件按真实速度回放为流，以及麦克风实时输入。输入转换是否由浏览器、设备程序或语音服务负责，按实际接口确定。

应用独立测试可使用已记录事件回放，必须带来源标记。纯事件回放验证的是应用处理能力，不证明新的音频经过真实语音服务。

建议使用成人模拟语音和虚构身份，包含平均分条件、分数表达、停顿、重叠和错误归属。双方共用参考题目，避免缺少图形上下文导致判断分歧。

## 7．联调验收

| 编号 | 场景 | 联合通过条件 |
|---|---|---|
| I01 | 正常发言 | 临时与定稿关联同一片段，时间定位正确 |
| I02 | 位置结果 | 标签含义可解释，不自动等同于学生姓名 |
| I03 | 重叠 | 多条记录或不确定状态可表示；音轨能力如实说明 |
| I04 | 重复与乱序 | 应用不重复存储，不被旧版本覆盖 |
| I05 | 定稿后修订 | 依赖旧版本的证据与建议进入失效流程 |
| I06 | 断流重连 | 续传不重复，缺失范围明确，已核验内容保留 |
| I07 | 音频回听 | 发言时间可定位到实际音频，过期链接不绕过权限 |
| I08 | 主动结束与失败 | 能区分完成、部分失败和不可用，不产生虚假成功 |
| I09 | 两种输入入口 | 真实流与文件回放产生可由同一适配层理解的结果 |

各方分别报告自己的能力，不把教学应用的展示效果当作语音算法提升证据。

## 8．接手方需确认的问题

2026年10月31日赛事补充：企业设备、DUI Open 账号和 Open-Bench 比赛专属数据均未取得。需补交终端实际型号与能力、服务或数据版本、使用许可、公开演示和云端处理限制、到期及删除规则。凭证与原数据不纳入公开仓库。只有转写标注、没有位置或教学标签时如实列出缺口；现阶段可继续合成事件开发。详见[赛事约束](../planning/赛事约束与规格调整.md)。

- 谁负责语音模块，现有服务在哪里，能否提供一份脱敏响应？
- 位置输出实际代表什么，是否与转写使用同一时钟和声源标识？
- 重叠分离是否交付，可否返回同片段原始与处理音轨？
- 本机或远端部署如何选择，当前设备、GPU、接口凭证是否可用？
- 真实接口联调前，哪份事件样例可作为双方共同测试基线？
